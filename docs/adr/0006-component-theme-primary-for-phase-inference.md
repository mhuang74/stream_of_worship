# Component-derived theme is the primary phase-inference signal for the songset constructor

The songset constructor previously fused a theme distribution for every song from four text/embedding sources (title + lyrics + song embedding + line embedding) and inferred worship-arc phase from it. Now, when a recording has component-level theme classifications (`song_components.theme`, 12-value vocabulary, chorus-preference aggregation weighted by `theme_confidence`), the constructor uses that component-derived distribution as the primary phase-inference signal; the fusion is demoted to fallback for the ~30% of pool songs without components (fallback + `has_components = false` flag, never a pool drop). Seasonal bias still applies after either path.

We chose components-primary because the chorus is what the congregation actually sings, so chorus-anchored theme classification is a stronger liturgical signal than whole-text embedding similarity, and the component classifications already exist — persisted per component and aggregated at recording level by the analysis pipeline (see ADR-0005 for the sibling posture decision). Full rationale, weights, and the six-way fitness renormalization this enables live in `specs/songset-constructor-component-metadata-integration-v1.md`.
